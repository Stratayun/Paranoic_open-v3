# Правила для агентов

Paranoic: Rust-ядро (`crates/`) + Kotlin Multiplatform/Compose (`ui/`), Android и Windows. Состояние — [ROADMAP.md](ROADMAP.md). Стек не менять.

## Работа

1. Делать код. Тесты, сборки и CI — только когда нужны для правки или когда владелец попросил. Маленький тест затронутого места — можно.
2. Всё готовое — в `main`, без force push, не теряя чужой код. Перед записью сверять актуальный `main`.
3. Сборки для телефона подписываются ключом проекта (`PARANOIC_KEYSTORE`, в CI — секреты `ANDROID_KEYSTORE_BASE64` / `ANDROID_KEYSTORE_PASSWORD`). Ключ и пароли в репозиторий не попадают.
4. Новые документы-планы, реестры и журналы не заводить. Состояние — коротко в ROADMAP, подробности — в сообщении коммита. Владелец сам сообщает, что не работает.
5. Отчёт коротко: что сделано, что проверено фактически, SHA. Не утверждать проверку без результата.

## Данные и безопасность

- Расшифрованное не покидает приложение; временные файлы с открытым текстом не создавать.
- Исходник не удаляется до подтверждённого результата; запись с неизвестным исходом не повторяется автоматически (request ID создаётся до отправки, повтор — только с тем же ID после сверки с журналом).
- Замена существующих файлов — только явно; перенос и корзина — без замены.
- Сейф изолирован от файлов и облака, не синхронизируется; Clear уничтожает ключи. Абсолютное стирание внешних копий не обещать.
- Пароль: от 12 символов, политика — `paranoic-notes::password_strength`, UI показывает её оценку и не решает сам.
- Секреты не логировать и не публиковать.

## Граница Rust ↔ Kotlin

- Rust: форматы, файлы, криптография, облако, политика; API — UniFFI в `crates/paranoic-bridge`. Kotlin: экраны, состояние, адаптеры ОС (Keystore, DPAPI).
- Блокирующие вызовы моста — через IO gateway, не на UI-потоке. Пароли и тексты передаются аргументами и не хранятся.
- Изменение API: сначала Rust-метод, затем Kotlin gateway и экран; заглушка не считается готовой интеграцией.
