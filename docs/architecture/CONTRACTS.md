# Технические договорённости

Контракты между Rust, мостом и Kotlin, которые нельзя нарушать при правках. Меняются вместе с кодом; это не журнал и не переписка.

- UniFFI: не экспортировать служебные `close`/`destroy`; используются `release_stream`, `erase_key`, `lock_all_secrets`. Все блокирующие вызовы — через IO gateway.
- Файловые операции: request ID создаётся до отправки; потерянный ответ сначала сверяется с журналом, повтор только с тем же ID. Move — Fail; замена только Copy file→file, без SAF. NativeJob.outcome/resultTarget — реальный исход/назначение.
- Attention: can_* решает Core; исходное предупреждение Reviewed только после Succeeded resolution job либо явного ручного решения. Неизвестное решение не повторять автоматически.
- Quick Lock: эпохи Rust/`secretCall` отсекают начатую раньше аутентификацию. Заметки — отдельные wrap/guard ключи, Clear/автостирание удаляют оба; Android 11+ strong biometric без credential fallback.
- Текст: `NativeFileVersion.blake3` — версия кодированных байтов; после Save modified_ms=None. Передавать всю версию. Новый `ReplaceContentExpected` не меняет старый `ReplaceExpected`.
- TXT/Markdown 2.4 / B1 (`46de6b3`): FileViewer направляет .txt/.md/.markdown в TextEditor. После У-67 (`29dc301`) редактирование ограничено 65 536 UTF-16 единицами; native-файл — 16 МиБ. Больший успешно прочитанный текст показывается только для чтения через LazyColumn фрагментами по 2048 с сохранением surrogate pair, без передачи всего текста в поле ввода. textOpen/textSave/textSaveAs вызываются через IO gateway; одна text-операция на gateway, слот удерживается до физического возврата native даже при отмене UI. Save передаёт всю исходную версию BLAKE3 и принимает только возвращённую версию; Core сохраняет исходную кодировку. Save copy создаёт новый UTF-8-файл в папке, зафиксированной при открытии, не заменяет файл и не переключает открытый документ. Changed сохраняет черновик и запрещает Save до перечитывания; неизвестный исход запрещает новые записи до явного осмотра/перечитывания, автоматического повтора нет. Навигация приложения и перечитывание подтверждают потерю правок, во время записи переходы блокируются. Блокировка/уход в фон закрывают экран и удаляют UI-черновик без сохранения на диск; о потере правок написано в редакторе. Сборка/проверка —.
- Office 2.6 / B2 подключён (`f813a12`): FileViewer выбирает экран по расширению DOCX/XLSX/ODS, формат байтов и лимиты проверяет Rust; officeOpen и преобразование DTO выполняются через IO gateway. Только структурный просмотр без исходной вёрстки, макросов и внешнего содержимого; предупреждение truncated обязательно. Строки таблиц ленивые, листы доступны по выбору, столбцы XLSX/ODS — по 8 на страницу; полный полученный текст ячейки открывается отдельно. Данные не сохраняются на диск; уход с экрана отменяет приём позднего результата и освобождает UI-состояние, но не прерывает синхронный native-вызов (У-15). Сборка/проверка нового экрана —.
- Архивы: host вызывает request-bound API через `ArchiveGateway`; один ID связывает подготовку/отмену/публикацию. Подготовка временная, пароль не журналируется. 7z — только `IsolatedSevenZip`, приватная пакетная `prepare_extraction`; поставка PDFium ещё нужна; код платформенной изоляции сохранён, проверка установленных worker остаётся.
- PublicationSpool: handoff до submit; при отказе/неизвестном ответе сохраняется для recovery. После подтверждённой успешной публикации удаляется (для extract также readback). Стартовая очистка сохраняет всё, на что ссылается журнал.
- WebDAV: generic bridge больше не подтверждает корзину за сервер. DELETE/удаление источника недоступны без проверенного профиля. Identity v2 различает origin/путь/аккаунт; старое подключение добавить заново, старые задания остаются привязаны к прежнему ID.
- Физический вызов SAF/провайдера нельзя безопасно убить; отменяется ожидание. Общий остаток синхронных preview/text/native вызовов — У-15. Гонки версий (У-24) и быстрый вход на телефоне (У-27) отдельны от блока 2.
- Блок 2 / PNG PDF и медиа: заголовок и размеры проверяются до пикселей, предел стороны 4096, принятого буфера RGBA — 64 МиБ. Android/desktop декодируют вне UI, не более одного native decode на процесс. Desktop — явный Codec.readPixels, без ленивого декодирования на render thread. Отмена отбрасывает/освобождает поздний bitmap, но не прерывает сам синхронный декодер. Код `d06b284`, проверка —.
- Блок 2 / worker (У-4, `4585698`, `fa724f3`): Linux/Android — seccomp allowlist/TSYNC; Windows — AppContainer с пустыми capabilities, точным handle list и job до ResumeThread. Нужен читаемый AppContainer установочный каталог; пользовательские ACL автоматически не расширяются. Обычный запуск worker на Windows запрещён.
- Android / worker: NativeRuntime.documentWorkersConfigure вызывается до PDF/7z; без host запуск запрещён. Закрытый isolatedProcess проверяет отличный от приложения UID, Core в нём недоступен. Только фиксированный decoder kind, Binder owner и два FD; пути данных/SAF grants не передаются. Пароль 7z идёт только как часть временного бинарного потока. Смерть клиента/сервиса и отмена закрывают каналы/убивают child; до чтения данных child ставит parent-death SIGKILL. Отказ изоляции не включает same-UID fallback. Проверка устройств —.
- Архивный source I/O (`fa724f3`): open/read/seek/metadata/list — фиксированный пул 2, проверка отмены при ожидании через 50 мс, deadline одного ответа 30 с, вход в занятый пул ≤ 5 с. Физически зависший вызов занимает слот до реального завершения. Поздний payload уничтожается/zeroize, после отмены новый source request не отправляется. Это не отмена уже начатой публикации Core и не обещание прервать ядро/чужой провайдер.
- Вложения заметок (Р-3, B8): `Note.attachments` передаётся при каждом сохранении без изменений — заметка, сохранённая без них, теряет вложения (объекты удаляются уборкой). Новое вложение: `notesAttachmentAdd` → ссылку добавить в заметку → сохранить тетрадь; несохранённые удаляются после блокировки. Перед сменой пароля сохранить заметки: несохранённые вложения при смене ключа отбрасываются. Просмотр — только внутри заметок через `notesAttachmentRead` (массив затирать после показа); экспорта наружу нет и не будет.

- B8 / UI (`273393f`): перед системным выбором файла тетрадь сохраняется. Picker хранит только временную import-capability и ID заметки, читает байты после повторного открытия заметок; Android ON_STOP не обходится. После Add ссылка включается в Note.attachments и тетрадь сохраняется; Remove также сохраняет тетрадь. При ошибке Save черновик ссылок остаётся, неизвестная запись не повторяется. До смены пароля Save обязателен; при его отказе смены нет. Превью не использует внешние приложения/clipboard/cache: PNG/JPEG/GIF/WebP с лимитом 4096×4096/64 МиБ пикселей либо начало UTF-8/UTF-16 текста до 128 КиБ с предупреждением. Байты затираются при закрытии/блокировке и при отменённой доставке; bitmap освобождается. Import ограничен фактическими 15 МиБ независимо от метаданных провайдера; UI показывает также 256 МиБ всего и 32 вложения на заметку. Проверка —.
- Пароли папок (B11): `vaultChangePassword` и `cryptomatorChangePassword` сначала проверяют старый пароль (`WrongPassword` — неверный). Копии старого заголовка или masterkey-файла вне этого хранилища (версии в облаке, бэкапы) по-прежнему открываются старым паролем — сказать об этом пользователю. `vaultSetRecovery` возвращает текст ключа: показать один раз, не сохранять, не логировать; новый ключ отменяет прежний. `cryptomatorOpen` сам доводит прерванную смену пароля — после неё нужен новый пароль. Перенос и замена в 1.8 (B12): `vaultMove` никогда не заменяет и не переносит папку внутрь неё самой; `vaultReplace` сохраняет имя в папке и отказывает (`Changed`), если файл изменился после начала.

- B4 / UI (`531e217`): «Ещё → Синхронизация и бэкап». Папки выбираются только по Core Location из подключённых пространств; Space.cloud — подсказка текущих WebDAV/reconnect-подключений, окончательную проверку стороны делает Rust. Режим backup/two-way и корзина сохраняются в паре. План явно показывается перед Run; все action 1–9 и report 1–8 имеют RU/EN подписи. Запуск/изменения и продолжение сохранённого плана — только по кнопке и подтверждению; автоматических повторов нет, задания обычные Core jobs. Конфликты из нового плана сначала сохраняют обе версии через conflict-copy; выбор версии доступен для записанных pair.conflicts. После Resolve/Forget исполнимый старый план сбрасывается и строится новый; если его задания уже приняты Core, сначала требуется syncRun прежнего плана (Busy на решение). Forget забывает путь и поддерево в baseline, не удаляет файлы. DeviceKey блокирует функции с понятным объяснением. Gateway выполняет блокирующие методы на Dispatchers.IO; UI при уходе не обещает прервать уже начатую native-операцию. Проверка —.

- B11/B12 / UI (`b8334df`): у открытой папки — смена пароля (старый, новый ≥ 12 символов, повтор; предупреждение о старых внешних заголовках/masterkey-копиях). Только 1.8: создание/замена ключа после подтверждения и пароля; одноразовый показ обычным Text без clipboard/export/saveable/log, закрытие/lock/pause удаляют ссылку из UI. Открытие по заранее созданному ключу не меняет пароль. B12: Move выбирает папку внутри того же открытого 1.8 из аутентифицированных списков; нельзя тот же parent, саму папку и её потомков. Replace подтверждает конкретный файл в хранилище и один выделенный источник из Files; имя сохраняется, источник не удаляется. Проверка Changed относится к версиям на старте native-операции, не к старому снимку UI. Все вызовы через IO gateway; на время операции общий guard блокирует вкладки, пространства и системный Back. Guard привязан к экрану и secretsEpoch, поздняя отмена старого экрана не освобождает guard нового. Ключи/диалоги очищаются при блокировке; неизвестная запись не повторяется, до дальнейших изменений нужно проверить исход и закрыть/открыть папку. Сборка/проверка UI —.

- B5 / UI (`69b7370`): все утверждённые экраны используют RU/EN для принадлежащих приложению подписей. ParanoicApp передаёт текущий язык корням Android/desktop; system-auth/notes biometric, picker и Android PlayerView получают его без перезапуска Core. Имена и содержимое файлов, идентификаторы, названия форматов и служебные данные Core остаются данными. Переключатели/подтверждения — одна подписанная focus/touch-область с Role и минимумом 48 dp; пользовательские строки/ячейки имеют видимый фокус и смысловые действия, заголовки — heading, обычные ошибки — polite live-region. Пароли, ключи и содержимое документов не помечаются live-region. Парольные поля получают password keyboard без автокоррекции; правила записи/подтверждений не меняются. Панели действий ограничены долей окна и прокручиваются, группы кнопок переносятся, длинные формы/диалоги доступны прокруткой; вложенные Lazy-списки имеют конечную высоту. Имена вложений/данные заметок, ключи и lifecycle очистки сохраняют B8/B11 контракты. Это кодовый проход: сборка, TalkBack, клавиатура на Windows, 200% шрифта и короткое окно проверяются отдельно на этапе C.

- У-53 / NotesScreen (`1a7a58e`): после обязательного Save успешная смена пароля инвалидирует старую UI-тетрадь и перечитывает её (ID вложений заменены). При ошибке чтения либо неизвестном исходе смены старая тетрадь недоступна для редактирования/Save; неизвестная смена не повторяется. Для продолжения нужен успешный Read. У-62: intrinsic/SubcomposeLayout панель заменена LazyRow со стабильными ID; это кандидат, без logcat/повтора на Android причина не подтверждена.
- У-66/67 / просмотр (`29dc301`): открытый файл показывается вне общего Scaffold/SpacesPanel, в полной области приложения. Просмотр PDF/фото/Office/медиа — панель поверх содержимого, скрытие/показ касанием плюс доступная кнопка возврата панели; pinch/double-tap и кнопки масштаба 1–6× с ограничением сдвига. Android PlayerView передаёт видимость контроллера панели просмотра. safeDrawing учитывает системные панели и вырезы; редактор дополнительно учитывает IME. Новые методы моста и внешние копии не добавлены. Android-регрессии подготовлены; сборка/выполнение/телефон —.

- E4.6 / настройки (`a465b17`): AppearanceScreen теперь хаб существующих настроек (Оформление, Файлы, Язык, Защита). Поиск RU/EN идёт по названиям/значениям настроек во всех разделах; содержимое пользователя и пароли не индексируются. Back сначала очищает поиск или возвращает к хабу, затем действует навигация приложения. AppearanceCodec/хранилища прежних настроек не меняются. Системный вход остаётся прежним платформенным контролом. Настройки отдельных хранилищ этой порцией не реализованы.
- E3.4 / Android (`a465b17`): FLAG_SECURE ставится до Compose; разрешение снимков/записи экрана хранится отдельно в noBackupFilesDir (AtomicFile, один строго проверяемый байт). Отсутствие, ошибка чтения и повреждение означают запрет. Включение — после предупреждения и подтверждённой записи; отключение ограничивает текущее окно до I/O. Настройка действует на окно приложения; диалог системного входа сохраняет свой SecureOn. Подготовлены три изолированных Android-теста политики; сборка/выполнение/фактические снимки на устройстве —.

## Стыки Rust ↔ Kotlin

- **У-11, SAF deletion:** `AndroidDocuments.deletion_supported(tree)` по умолчанию false; `delete(tree, document, directory)` получает ожидаемый тип (false = файл, true = пустая папка). Разрешено только для локального `com.android.externalstorage.documents`, распознанного primary/UUID-тома, действующего write-grant и разрешённого прямого доступа к памяти. Android проверяет принадлежность document ID дереву, запрещает корень grant, чужой том, выход по `..` и открывает родительские каталоги без перехода по симлинкам. Host-only `saf_delete_at(parent_fd, name, directory)` дублирует удерживаемый FD через `/proc/self/fd` и выполняет в Rust атомарный unlink/rmdir через cap-std. Никакого `deleteDocument`, рекурсивного fallback или автоматического повтора. Без этих гарантий удаление возвращает Unsupported до мутации. Непустой staging bundle сохраняется с NeedsAttention. Смена callback ABI требует свежих UniFFI bindings и native-библиотеки из той же версии; генератор сборки делает это автоматически. Реальные SAF/FUSE/SD-карта проверяются отдельно на телефоне.

Вызовы `NativeRuntime` (UniFFI), все блокирующие — через IO gateway. Пароли и тексты — только аргументами, не хранить.
- **E2.1 архивы:** `NativeArchiveEntry.encrypted`; новая ошибка `PasswordRequired` (архив зашифрован, пароль не дан) и `WrongPassword` (неверный пароль или повреждённые зашифрованные данные; у 7z нет проверочного значения). Без пароля и с неверным паролем ничего не записывается. Kotlin подключён: `fc64d3a` (признак шифрования, отдельные ошибки и окно пароля); native/телефон —.
- **E2.6 большие тексты (только чтение):** `text_pager_open(location) → {handle, rows, encoding, bytes}` (один проход, до 1 ГиБ; строка — до перевода строки или 16 КиБ текста); `text_pager_read(handle, first, count ≤ 2000) → [String]` без переводов строк; `Changed`, если файл уже не та версия; `text_pager_close(handle)`. Одновременно до 8, самый старый закрывается при девятом (`Invalid` на чтении). Редактирование — прежний `text_open`/`text_save` до своего лимита. Kotlin подключён: `fc64d3a`, окно 128 строк/фрагментов и закрытие handles при отмене/выходе. В текущем экспорте pager encoding = 0/1/2/3 (UTF-8/BOM/UTF-16 LE/BE), а text_open = 1/2/3/4; адаптер сопоставляет отдельно. Сборка/native/устройства —.
- **E2.3:** `vault_probe(folder) → {vaults[{location, name, kind 1=1.8 / 2=Cryptomator}], unchecked}` — до пароля.
- **E3:** `diagnostics_recent`, `diagnostics_clear`, `diagnostics_report`, `diagnostics_report_text` (без имён и путей).
- **E5.1 «Сейф»:** `safe_open() → handle` для обычных `vault_*` (нужны открытые заметки; `Locked` иначе); `safe_clear() → guarantee` — «Очистить всё» (заметки + «Личная папка»). Папка `.pnc-safe` скрыта из `list`. Kotlin подключён: `c6c4cad` / `11e23c7` — вкладка личных файлов, защищённая копия, внутренний move/rename/delete/mkdir/export, общий safe_clear; Core-путь Safe и OS grant UI не создаёт. Остаток: E4.7, входящий Move/Share и У-68.
- **E5.2:** `notes_set_duress(Some/None)` (`WeakPassword`; `Invalid` — совпадает с основным), `notes_duress_enabled()`. Срабатывание внутри `notes_unlock` выглядит как обычный успешный вход; UI ничего не показывает и не различает. Kotlin подключён: `058f8fe` / `11e23c7` — состояние/настройка/удаление, предупреждение до настройки.
