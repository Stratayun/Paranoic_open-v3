# Идеи для удобного интерфейса (наброски)

Поиск по другим приложениям и исследованиям, 2026-11-14. Только идеи и логика: чужой код и оформление не переносятся. Каждый пункт: идея → откуда → как это может выглядеть в Paranoic. Отбирать и решать будем вместе; к [PLAN.md](../../PLAN.md) и [vault-explorer-ux.md](vault-explorer-ux.md).

## Главный принцип

Исследование «Why Johnny Can't Encrypt» (Whitten, Tygar, 1999): защитная программа удобна, только если пользователь **понимает, какие задачи безопасности ему нужно выполнить, может понять, как их выполнить, не совершает опасных ошибок и не бросает программу из-за неудобства**. Повторное исследование в 2015 году показало, что многие инструменты шифрования до сих пор этому не соответствуют. Для Paranoic это критерий проверки каждого экрана: понятно ли, что делать, и можно ли случайно навредить себе.

## Идеи

1. **Проверка, что ключ восстановления записан.** Сейчас ключ показывается один раз, и окно закрывается кнопкой. Лучше: после «Записал(а)» попросить ввести две-три случайные группы из ключа (как подтверждение фразы восстановления в кошельках). Не совпало — ключ показывается снова, ключ ещё не потерян. *Откуда:* аварийный набор 1Password, общая практика «проверить восстановление до того, как оно понадобится». → 8, У-50.
2. **«Набор восстановления» для печати.** Страница с ключом восстановления, названием папки и инструкцией, печатается через системную печать Android, без сохранения файла в приложении. Совет хранить бумагу отдельно от устройства. *Откуда:* Emergency Kit 1Password (PDF с данными и местом для пароля). Нужно решение: печать — это выход ключа из приложения, хоть и по воле пользователя.
3. **Первый запуск — короткий мастер.** Язык → блокировка приложения → пароль заметок → первая зашифрованная папка → ключ восстановления. Каждый шаг можно пропустить. Цель — уложиться в несколько минут: многие бросают настройку, если она длиннее примерно десяти минут или требует технических знаний. *Откуда:* обзоры менеджеров паролей для новичков.
4. **«Состояние защиты» — один экран.** Список с понятными действиями:
   - у каких папок нет ключа восстановления;
   - где слабый пароль;
   - выключена блокировка приложения;
   - разрешены скриншоты;
   - формат 1.8 ещё не прошёл аудит;
   - есть задания «требует внимания»;
   - есть конфликты синхронизации;
   - после смены пароля в облаке остались копии старого заголовка.

   Каждый пункт ведёт туда, где это исправляется. *Откуда:* проверки безопасности в менеджерах паролей.
5. **Индикатор силы пароля с конкретным советом**, а не просто «слабый»: «слишком короткий», «это частое слово», «добавьте ещё одно слово». Исследование CHI 2017: подробная обратная связь даёт более надёжные и не менее запоминающиеся пароли, чем полоска силы. Индикатор подсказывает, но не блокирует (кроме явного минимума). В ядре уже есть оценка силы для заметок — распространить на папки и Cryptomator. *Откуда:* zxcvbn (Dropbox), CHI 2017.
6. **Генератор фраз-паролей** рядом с полем пароля: 5–6 случайных слов, показ, копировать нельзя, только запомнить или переписать. *Откуда:* NIST SP 800-63B (длина важнее состава символов, без обязательной периодической смены).
7. **Каждая ошибка — с «что делать».** «Нет доступа» → «Папка выдана только для чтения. Выдайте папку из памяти телефона» + «Подробнее» (код ядра). Пользователи Cryptomator жалуются на сложный интерфейс и отсутствие подсказок по устранению проблем прямо в приложении. *Откуда:* отзывы о Cryptomator (G2). → 2–4, 8.
8. **Список хранилищ можно упорядочить перетаскиванием; биометрия включается для каждого хранилища отдельно.** *Откуда:* документация Cryptomator для Android.
9. **Хранилища в системном приложении «Файлы».** Каждое хранилище видно там отдельным пунктом; заблокированное открывается прямо оттуда. *Откуда:* Cryptomator (Document Provider). Риск: открытое хранилище становится доступно другим приложениям. Только по явному включению для конкретного хранилища, позже.
10. **Честно о границах защиты.** Короткий экран «Что защищено и что нет» для каждого формата. Например: Cryptomator не видит удаления последних блоков; копии старого заголовка в облаке; скриншоты; что видно серверу. *Откуда:* Tella («не бывает приложения, защищённого на 100%»). У нас эти тексты разбросаны по экранам — собрать в одно место.
11. **Быстрое удаление одним действием** с подтверждением. У нас есть Clear для заметок; обсудить такое же для выбранных хранилищ. *Откуда:* Tella (Quick Delete).
12. **Отмена вместо подтверждения** там, где действие обратимо: убрать хранилище из списка, закрыть вкладку → «Отменить» на несколько секунд. Подтверждение — только для необратимого (удаление, Clear). *Откуда:* Vault Explorer, Material Design.
13. **Пустые экраны учат.** Вместо «Папка пуста» — что можно сделать отсюда и одна главная кнопка. *Откуда:* Vault Explorer, общие правила Material.
14. **Прогресс словами при долгих операциях** (вывод ключа из пароля, проверка, синхронизация) и кнопка «Отмена», где отмена безопасна. *Откуда:* Vault Explorer.
15. **Современный Android:** отрисовка под системными панелями (с Android 15 это обязательно для приложений с targetSdk 35+, у нас 36), анимация жеста «назад» с предпросмотром, адаптивная раскладка для планшетов и складных (две панели). *Откуда:* рекомендации Android и Material 3 Expressive (Files by Google). Проверить на телефоне, что наши экраны не залезают под панели.
16. **Работа без сети как норма:** всё, кроме облака, работает офлайн, и интерфейс это явно показывает (облачные пункты помечены, а не просто падают с ошибкой). *Откуда:* Tella.
